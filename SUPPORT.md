# Support

RPS Arena is an open-source project. Use the channel that best matches the problem so reports can be handled without exposing unnecessary data.

## Bugs and feature requests

For reproducible application bugs and public feature requests, use the repository issue forms in `.github/ISSUE_TEMPLATE/`.

Include:

- platform and OS version;
- RPS Arena version or commit SHA;
- concise reproduction steps;
- expected behavior;
- observed behavior;
- whether local settings/history/profiles were affected;
- sanitized logs only when they are relevant.

Do not paste backup text, credentials, private keys, access tokens, personal information, or other sensitive data into a public issue.

## Security issues

Do not report an undisclosed vulnerability through a normal public issue. Follow `SECURITY.md` and prefer GitHub private vulnerability reporting when available.

## What support covers

Support can help with:

- build/setup problems documented by the project;
- reproducible application defects;
- accessibility regressions;
- backup-format/import problems using synthetic or redacted examples;
- documentation issues;
- contribution questions;
- release artifact problems.

Support does not require users to provide passwords, tokens, signing keys, full device backups, or unrelated personal information.

## Troubleshooting first

Before opening an issue, check:

- `docs/setup.md`
- `docs/testing.md`
- `docs/troubleshooting.md`
- `docs/release.md`
- existing open/closed issues for the same symptom.

When possible, run the platform-appropriate local verifier and include only its non-sensitive failure output.
