# RPS Arena v0.1.1 Release Checklist

Use this checklist for the final `v0.1.1` release. Complete every applicable verification item against the exact commit that will receive the tag.

## 1. Public baseline

- [ ] Public `v0.1.0` exists and points to the intended baseline.
- [ ] `v0.1.1` contains only the reviewed changes since `v0.1.0`.
- [ ] No stale release claim remains in the release documentation.

## 2. Source quality

- [ ] `python3 scripts/check_format.py`
- [ ] `python3 scripts/check_docs_links.py`
- [ ] `python3 scripts/check_docs_coverage.py`
- [ ] `python3 scripts/check_for_secrets.py`
- [ ] `python3 scripts/check_android_privacy.py`
- [ ] `python3 scripts/check_version.py`
- [ ] `python3 scripts/verify_localizations.py`

## 3. Automated tests

- [ ] `gradle :shared:allTests --stacktrace`
- [ ] `gradle :shared:desktopTest --stacktrace`
- [ ] `gradle :shared:assembleAndroidDeviceTest --stacktrace`
- [ ] `gradle :androidApp:lintDebug --stacktrace`
- [ ] `gradle :androidApp:assembleDebug --stacktrace`
- [ ] `gradle :desktopApp:classes --stacktrace`
- [ ] `gradle :webApp:composeCompatibilityBrowserDistribution --stacktrace`
- [ ] `cargo test --manifest-path rust-engine/Cargo.toml --all-targets`
- [ ] iOS simulator framework/Xcode validation passes on the supported macOS runner.

## 4. Security and privacy

- [ ] Security workflow is green on the exact release commit.
- [ ] CodeQL is green on the exact release commit.
- [ ] No new secret, credential, analytics, advertising, or unnecessary network permission was introduced.
- [ ] Offline-first behavior remains accurate in the README and release notes.

## 5. Release artifacts

- [ ] Tag is created from the exact validated `main` commit.
- [ ] Release packaging completes successfully.
- [ ] Android artifact is present where configured.
- [ ] Desktop artifacts are present where configured.
- [ ] Web artifact is present where configured.
- [ ] iOS validation artifacts are present where configured.
- [ ] Rust artifacts/tests are present where configured.
- [ ] SHA-256 checksums are generated.
- [ ] Every checksum matches the corresponding published artifact.

## 6. GitHub release metadata

- Tag: `v0.1.1`
- Target: `main`
- Suggested title: `RPS Arena v0.1.1 — Reliability & Quality Patch`
- Release type: patch / development release
- Pre-release: enable if the project is still treating the public `0.x` line as preview-quality.
- Latest release: enable when this is the newest public release.
- Discussion: optional; enable only if a release discussion will be actively maintained.
- Assets: attach only verified release artifacts and checksums.

## 7. Post-publication verification

- [ ] Release page renders correctly.
- [ ] Tag points to the intended commit.
- [ ] Release assets download successfully.
- [ ] Checksums can be independently verified.
- [ ] README release section reflects the published state.
- [ ] Changelog/release notes match the actual `v0.1.0...v0.1.1` diff.
- [ ] Any release-blocking issue is linked and tracked.

## Release command reference

After all gates are green, a local tag can be created from the validated commit with:

```bash
git checkout main
git pull origin main
git tag -a v0.1.1 -m "RPS Arena v0.1.1 — Reliability & Quality Patch"
git push origin v0.1.1
```

Alternatively, GitHub's release UI can create the tag while creating the release. Never tag a moving or unverified commit.
