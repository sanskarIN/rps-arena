# RPS Arena v0.1.4 Plan

## Objective

Prepare the next public patch release after `v0.1.3`, with emphasis on cross-platform reliability, regression depth, release reproducibility, and maintainability without expanding the product's offline-first boundary.

## Priorities

1. **Gameplay state reliability**
   - Expand match-state invariant coverage for best-of-3, best-of-5, endless, streak, and tournament modes.
   - Verify score, draw, finish, and round-record consistency at boundary conditions.

2. **Persistence and recovery**
   - Exercise persistence fallback behavior and corrupted local-state recovery.
   - Preserve backup compatibility and avoid undocumented schema changes.

3. **Accessibility and localization**
   - Add regression coverage for semantic UI tags, reduced-motion behavior, and English/Hindi catalog parity.
   - Keep user-facing terminology stable unless a correction is demonstrably needed.

4. **Cross-platform confidence**
   - Improve CI coverage and release evidence for Android, iOS/iPadOS, desktop, Web, and the optional Rust rules engine.
   - Separate platform-host limitations from genuine product failures in documentation.

5. **Release engineering**
   - Keep release checklists evidence-based and tied to the final `main` revision.
   - Publish only verified artifacts and checksums.

## Non-goals

- No mandatory accounts or cloud sync.
- No analytics or advertising SDKs.
- No production network multiplayer service.
- No large architecture rewrite.
- No artificial/no-op commits.

## Exit criteria

- Focused changes are covered by automated tests.
- Repository formatting, documentation, privacy, secret, version, and localization checks pass.
- Cross-platform CI is green or documented with a justified platform limitation.
- Security checks are green.
- `v0.1.4` release notes match the actual diff.
- The release tag targets the final verified `main` commit.
